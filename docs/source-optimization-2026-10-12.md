## Архитектура и область изменения

TMDB предоставляет метаданные. React-плеер получает кандидатов постепенно
через `/api/source-host?op=discover`; сервер Lampac разрешает конкретную озвучку
и серию, проверяет медиа и возвращает подписанные HLS/прямые файлы.
Переключение источника, озвучки и качества использует существующий клиент.
Публичный сервер источников: `https://lampa-source-host.vercel.app`;
фронтенд: `https://lampa-stream-six.vercel.app`.

Изменены только порядок обхода TV-озвучек в `source-host/providers/lampac.mjs`
и его регрессия в `source-host/tests/lampac.test.mjs`.
Активный вариант уже есть в ответе провайдера, но ранее альтернативная озвучка,
стоящая раньше него, задерживала выдачу готового результата своим HTTP-запросом
до 12 секунд. Теперь готовый вариант идёт первым; остальные сохраняются в
исходном порядке. Общая очередь, три параллельных запроса, отмена, валидация
сезона/серии и безопасность медиа не менялись. Новых зависимостей нет.

Регрессия сначала падала, затем прошла: медленная альтернатива заблокирована,
активная озвучка приходит сразу; после разблокировки доступны все три озвучки
с точными season=3, episode=14. Серверные тесты: 33/33, проверки клиента и
плеера прошли; синтаксис и `git diff --check` прошли.

текущую доступность. Filmix partial-file расследуется отдельно; менять
Range по одной гипотезе нельзя. На этом этапе проверка качеств/озвучек
и измерение оставшихся задержек ещё не были завершены; результаты

480p и прошёл FFmpeg startup (1,63 с) + seek60 (2,15 с). Запрос bytes=0-

8MiB clamp не подтверждена этим случаем. Range не менялся. Повторный успех

Chromium повторно проверил BB S1E1 / Vibix 720p: startup=12,032 с,
длительность 3495,671 секунды, 28 кадров до seek и 35 после seek60,

## Дополнительные озвучки, качества и время запуска

Повторяемая проверка: `node scripts/check-source-voices-live.mjs`;
самопроверка без сети: та же команда с `--self-check`.
Обезличенные результаты сохранены в
`docs/source-voices-verification-2026-10-12.json`; подписанные URL и ответы
провайдеров в репозиторий не записываются. Время всего запуска ограничено
пятью минутами, каждого декодирования — 25 секундами, параллелизм — три.

На production проверены семь озвучек и десять сочетаний качества/озвучки;
девять прошли настоящее декодирование кадра на старте и после seek60:

- Fight Club: Vibix, русский дубляж 480p/1080p; VideoHUB auto.
- Breaking Bad S1E1: HDVB «Дубляж», auto.
- Haikyuu S1E14: AniMedia auto; Kodik AniLibria.TV и AniDUB, по 360p/720p.

HDVB LostFilm превысил 25-секундный предел. Filmix в этой выдаче отсутствовал;
Vibix для BB тоже отсутствовал, хотя предыдущий настоящий поток работал.
Все три записи получили хотя бы один проверенный вариант; незапущенных
заданий и превышения общего предела не было. Проверены точные season/episode.

Повторное измерение Chromium на живых ранее полученных Vibix 720p:
Fight Club запустился за 3,925 с, BB S1E1 — за 3,350 с. В измерение входит
одна секунда воспроизведения до контрольного условия. HLS получил headers
за 1,069–1,123 с, первый segment — за 0,533–0,782 с; Node → Worker redirect
занял 0,156–0,179 с. Это измерение тёплого запуска, а не доказательство
устранения прежних 12–13 с или предела задержки всего каталога.

Worker перед каждым ресурсом обращается к защищённому `/v1/media-route`;
для HLS затем обращается к Node ещё раз. Кеш не добавлялся: случайные токены
новых сегментов не переиспользуются, а проверку срока и DNS нельзя ослаблять.
Прямые Worker root-ссылки тоже не вводились: frontend API проверяет origin
Node, и изменение этого контракта ради измеренных 160–180 мс потребовало бы
новой конфигурации и отдельного выпуска frontend. Существующий безопасный
маршрут сохранён; дополнительных запросов или зависимостей не добавлено.

Результат исследования приложенных проектов:
[Tape-Operator](https://github.com/Kirlovon/Tape-Operator/blob/298a4617a89ef5a09d1eccd6731ad6318dee1f10/player/player.js)
встраивает Kinobox iframe;
[Kinobox API](https://kinobox.tv/api) ограничивает запросы;
[movie-web archive](https://github.com/M1noa/movie-web-archive/blob/f7dd28cbe0c33753a16736285c96e52791efbdcb/package.json)
зависит от старой версии providers. Не подтверждённые прямые потоки

используются существующим адаптером; LeProduction/Mirage/Animebesst/RuDub

Ограничения: проверена выборка, а не весь каталог и не полные фильмы;
upstream меняются между запросами. Новых платных услуг не подключалось.
MCP не возвращает billing plan команды, а billing API не подтвердил сумму:

контейнерный runtime сам по себе не означает бесплатный хостинг.

Финальные локальные проверки этого прохода: source-host 33/33, Worker 12/12,

## Проверка условия $0 и локального резерва

Следующий проход проверил billing charges текущей Vercel-команды за
1–12 октября (до 13 октября UTC): снова 404 `costs_not_found`, не нулевая
сумма. `get_team` и `list_teams` вернули name/slug/id/saml без `billing.plan`.
CLI Vercel в текущем окружении отсутствует. Поле тарифа не было подменено
догадкой о Hobby и секреты для обхода подключённого MCP не извлекались.

Официальные [Functions pricing](https://vercel.com/docs/functions/usage-and-pricing)
и [Hobby](https://vercel.com/docs/plans/hobby) указывают отсутствие on-demand
usage для Hobby. На Pro действует базовая плата и оплачиваемое потребление;
[Spend Management](https://vercel.com/docs/spend-management) не обеспечивает
строгое мгновенное ограничение расходов. Для исходного требования нужен
подтверждённый Hobby; документация не подтверждает тариф данной команды.

Cloudflare `GET workers/subdomain` ответил 200 и подтвердил аккаунт
`ocr-gemini-proxy`, которому принадлежит действующий media Worker. Но чтение
subscriptions этого же аккаунта отклонено: API 10000 Authentication error.
Следовательно, живой Workers Free тоже не подтверждён этим billing-запросом.
Требуемые [Free limits](https://developers.cloudflare.com/workers/platform/limits/#daily-requests)
конечны и допускают остановку при исчерпании квоты, а не покупку Paid.
Подписки, upgrades и новые платные услуги не создавались.

Локальный Docker подтвердил permission denied для своего socket. Проверка
другого пути обнаружила dotnet host 10.0.11 с NETCore runtime, но без ASP.NET
Core, SDK и Lampac Core.dll. Поэтому готовность Docker или нативного сервера
не объявлялась по одному наличию команды dotnet. Для запуска под текущим
пользователем выбран готовый pinned Lampac release и ASP.NET Core runtime
в отдельном private-каталоге; системный installer с sudo не используется.

## Локальный сервер: запущен и проверен

На 13 октября по Europe/Minsk (12 октября UTC) локальный резерв установлен
в `/mnt/nvme/camera/lampa-stream-vercel/local-runtime` вне Git. Каталог имеет
mode 0700, независимые local secrets — 0600. Production-секреты не читались.
Использованы готовый Lampac 1.81.0 и ASP.NET Core 10.0.12, без SDK, Docker,
root, apt или новой облачной услуги. SHA-256 release и SHA-512 runtime
независимо пересчитаны и совпали с официальными metadata. Три существующих
native patcher применены к локальному release.

Движок слушает `127.0.0.1:19118`, Node API — `127.0.0.1:19120`, CDP —
`127.0.0.1:19222`. После полного перезапуска повторно прошли health 200,
Chromium ping, CDP version, native Playwright sentinel и Vibix frame/seek60.
Проверены текущие процессы и loopback listeners; 51 модуль скомпилирован.
Сервер оставлен работающим. Это API-резерв на данном компьютере, не новое
публичное размещение и не переключение production frontend на localhost.

Локальный поиск Fight Club дал 38 кандидатов от девяти провайдеров за
14,18 с (полная выдача, не время первого кандидата). Filmix 480p MP4 и
Vibix 720p HLS декодировали кадр на старте и после seek60. Начальные ошибки
HLS-harness не записаны как outage: после добавления существующих FFmpeg9
флагов для подписанных extensionless HLS Vibix прошёл оба контроля.

Отдельный настоящий Chromium запустил Haikyuu S1E14 через Kodik
AniLibria.TV 720p за 1,472 с: duration 1470,143 с, 27 кадров на старте,
42 после seek60, readyState 4. Все браузерные запросы медиа шли на
`127.0.0.1:19120`, через локальный Node; Vercel/Worker не участвовали.
Обезличенные данные — `docs/source-local-verification-2026-10-13.json`.
Первая попытка AniMedia не прошла assertion; отдельный повтор resolve дал
200, точные S1E14 и HLS. Причина первого отказа не установлена, стабильность
AniMedia этим не подтверждается.

Установленный launcher:
`python3 /mnt/nvme/camera/lampa-stream-vercel/local-runtime/bootstrap.py`.
Он проверяет private modes, свободные порты и готовность; ошибки запуска
останавливают только созданные им subprocess handles. Повторный запуск при
занятых портах проверенно отклоняется и сохраняет текущие PID и ready marker.
Инструкция, официальные metadata и decoded-frame proofs хранятся в private
каталоге; секреты и подписанные ответы в репозиторий не внесены.

Ограничение: найденный Xvfb — заглушка `/bin/true`; native и CDP Chromium
работают headless. Источники с headed browser challenges не подтверждены.
Не проверялись полный каталог, полные фильмы и реальные TMDB credentials.
