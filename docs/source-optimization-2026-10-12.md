## Архитектура и область изменения

TMDB предоставляет метаданные. React-плеер получает кандидатов постепенно
через `/api/source-host?op=discover`; сервер Lampac разрешает конкретную озвучку
и серию, проверяет медиа и возвращает подписанные HLS/прямые файлы.
Переключение источника, озвучки и качества использует существующий клиент.
Публичный сервер источников: `https://lampa-source-host.vercel.app`;
фронтенд: `https://lampa-stream-six.vercel.app`.

Изменены только порядок обхода TV-озвучек в `source-host/providers/lampac.mjs`
и его регрессия в `source-host/tests/lampac.test.mjs`.
Активный вариант уже есть в ответе провайдера, но ранее альтернативная озвучка,
стоящая раньше него, задерживала выдачу готового результата своим HTTP-запросом
до 12 секунд. Теперь готовый вариант идёт первым; остальные сохраняются в
исходном порядке. Общая очередь, три параллельных запроса, отмена, валидация
сезона/серии и безопасность медиа не менялись. Новых зависимостей нет.

Регрессия сначала падала, затем прошла: медленная альтернатива заблокирована,
активная озвучка приходит сразу; после разблокировки доступны все три озвучки
с точными season=3, episode=14. Серверные тесты: 33/33, проверки клиента и
плеера прошли; синтаксис и `git diff --check` прошли.

ответ billing API `costs_not_found` не доказывает отсутствие расходов.

основной alias указывает на него. Deployment file API подтвердил новый SHA1

Chromium с реальными HLS этого выпуска: Fight Club / Vibix 720p, 28 кадров

текущую доступность. Filmix partial-file расследуется отдельно; менять
Range по одной гипотезе нельзя. На этом этапе проверка качеств/озвучек
и измерение оставшихся задержек ещё не были завершены; результаты
следующего прохода приведены ниже.

Отдельный свежий Filmix / Fight Club resolve после указанного сбоя дал MP4
480p и прошёл FFmpeg startup (1,63 с) + seek60 (2,15 с). Запрос bytes=0-
шёл через Worker и получил 200 video/mp4 без Content-Range/Content-Length.
FFmpeg с принудительным request_size=4194304 дал EOF; гипотеза о Node

не объясняет первый partial-file и не является доказательством стабильности.

Chromium повторно проверил BB S1E1 / Vibix 720p: startup=12,032 с,
длительность 3495,671 секунды, 28 кадров до seek и 35 после seek60,

реальные кадры получены с production, UI-меню и TMDB API отдельно не проверялись.

## Дополнительные озвучки, качества и время запуска

Повторяемая проверка: `node scripts/check-source-voices-live.mjs`;
самопроверка без сети: та же команда с `--self-check`.
Обезличенные результаты сохранены в
`docs/source-voices-verification-2026-10-12.json`; подписанные URL и ответы
провайдеров в репозиторий не записываются. Время всего запуска ограничено
пятью минутами, каждого декодирования — 25 секундами, параллелизм — три.

На production проверены семь озвучек и десять сочетаний качества/озвучки;
девять прошли настоящее декодирование кадра на старте и после seek60:

- Fight Club: Vibix, русский дубляж 480p/1080p; VideoHUB auto.
- Breaking Bad S1E1: HDVB «Дубляж», auto.
- Haikyuu S1E14: AniMedia auto; Kodik AniLibria.TV и AniDUB, по 360p/720p.

HDVB LostFilm превысил 25-секундный предел. Filmix в этой выдаче отсутствовал;
Vibix для BB тоже отсутствовал, хотя предыдущий настоящий поток работал.
Все три записи получили хотя бы один проверенный вариант; незапущенных
заданий и превышения общего предела не было. Проверены точные season/episode.

Повторное измерение Chromium на живых ранее полученных Vibix 720p:
Fight Club запустился за 3,925 с, BB S1E1 — за 3,350 с. В измерение входит
одна секунда воспроизведения до контрольного условия. HLS получил headers
за 1,069–1,123 с, первый segment — за 0,533–0,782 с; Node → Worker redirect
занял 0,156–0,179 с. Это измерение тёплого запуска, а не доказательство
устранения прежних 12–13 с или предела задержки всего каталога.

Worker перед каждым ресурсом обращается к защищённому `/v1/media-route`;
для HLS затем обращается к Node ещё раз. Кеш не добавлялся: случайные токены
новых сегментов не переиспользуются, а проверку срока и DNS нельзя ослаблять.
Прямые Worker root-ссылки тоже не вводились: frontend API проверяет origin
Node, и изменение этого контракта ради измеренных 160–180 мс потребовало бы
новой конфигурации и отдельного выпуска frontend. Существующий безопасный
маршрут сохранён; дополнительных запросов или зависимостей не добавлено.

Результат исследования приложенных проектов:
[Tape-Operator](https://github.com/Kirlovon/Tape-Operator/blob/298a4617a89ef5a09d1eccd6731ad6318dee1f10/player/player.js)
встраивает Kinobox iframe;
[Kinobox API](https://kinobox.tv/api) ограничивает запросы;
[movie-web archive](https://github.com/M1noa/movie-web-archive/blob/f7dd28cbe0c33753a16736285c96e52791efbdcb/package.json)
зависит от старой версии providers. Не подтверждённые прямые потоки
не выдавались за новые рабочие источники. Native провайдеры Lampac уже
используются существующим адаптером; LeProduction/Mirage/Animebesst/RuDub
не требуют дублирующих интеграций.

Ограничения: проверена выборка, а не весь каталог и не полные фильмы;
upstream меняются между запросами. Новых платных услуг не подключалось.
MCP не возвращает billing plan команды, а billing API не подтвердил сумму:
абсолютное отсутствие облачных расходов этим не доказано.
Официальная [документация контейнерных функций Vercel](https://examples.vercel.com/kb/guide/does-vercel-support-docker-deployments)
указывает те же Active CPU тарифы и лимиты, что у обычных функций;
контейнерный runtime сам по себе не означает бесплатный хостинг.
