# Новый хост источников

Цель — независимый от vi3000 сервер фильмов, сериалов и аниме с русскими озвучками, несколькими качествами, точным выбором серии и проверенным воспроизведением. Клиент старого сайта не задаёт архитектуру нового сервера.

## Архитектура

- Отдельный Node API и закреплённый Lampac NextGen `1.81.0` с Chromium работают в одном Vercel Container Runtime. Browser запускается скрыто в Xvfb; Lampac и CDP доступны только внутри контейнера. Образ уже собран удалённо, модульный кэш подготовлен заранее и копируется в эфемерный `/tmp` при старте.
- Поиск источников возвращает результаты постепенно. Идентификатор кандидата содержит зашифрованное состояние с ограниченным сроком жизни, поэтому выбранная озвучка переживает смену инстанса без общей памяти. Приватные API требуют серверный ключ; ссылки воспроизведения непрозрачны и подписаны.
- Node API проверяет URL, DNS и каждый redirect. Он обслуживает HTTP Range и HLS, включая относительные сегменты, ключи, init-сегменты и субтитры. Адреса и заголовки поставщика не принимаются от пользователя.
- По умолчанию видео передаётся через Node API контейнера. Необязательный `SOURCE_MEDIA_RELAY_URL` подключает отдельный Cloudflare Worker для потоковой доставки крупных прямых файлов в обход ограничения размера ответа Vercel. Worker получает URL через приватный `GET /v1/media-route` с Bearer-ключом, а ресурсы движка запрашивает у `GET /v1/media` с `x-source-relay-key`. Секреты существуют только на сервере.
- Чтобы холодный запуск не тратил ресурсы без необходимости, Node API стартует первым, а Lampac и браузер поднимаются при первом поиске или разрешении источника. Предварительный модульный кэш сокращает запуск, но не делает его постоянным. Источники и профили Chrome могут потеряться при перезапуске.

## Текущее состояние

Отдельный Vercel source host развёрнут по адресу `https://lampa-source-host.vercel.app` (последний READY deployment `dpl_8spgCHP2jHu7xABfaNDKLTD4YtG2`); его контейнер размещён во Frankfurt (`fra1`). В настройках **Project Settings → Functions → Default Regions** также нужен Frankfurt: одного `regions` в `vercel.json` недостаточно, чтобы переместить сам контейнер. Фронтенд READY (`dpl_7FUZhCKsUnNGKAvPwj6iMX5E2ybd`) использует собственный source host в разделе «Источники»; встроенный Collaps оставлен как явный резервный источник.

Cloudflare Worker доставки видео развёрнут по адресу `https://lampa-source-media.ocr-gemini-proxy.workers.dev` и подключён к source host через `SOURCE_MEDIA_RELAY_URL`. Для Fight Club/Vibix 1080p и BB/Vibix подтверждены декодирование FFmpeg и seek на 60-й секунде; BB также прошёл реальные браузерные проверки кадра и меню. Свежие скрытые браузерные проверки декодировали кадры BB S1E1 и Haikyuu S1E14/S3E1; AniSkip вернул тайминги, а кнопку «Пропустить опенинг» на S3E1 удалось нажать. Таймаут на 90-й секунде относится только к BB-кандидату ZetflixDB, а не к BB/Vibix. Haikyuu прошёл живую проверку этих эпизодов, но покрытие аниме в целом остаётся частичным. Метаданные TMDB брались из fixtures, без реального API-токена. Актуальные проверки: source-host 22/22, Worker 8/8 и Playwright 13/13 (43 всего); также прошли client assertion checks и build. Изолированная публикационная копия отдельно прошла 22/22.

Свежий ZetflixDB для фильма разрешается и возвращает HLS, но запрос сегмента через Worker завершается 502 из-за upstream 5xx. Кандидат BB/ZetflixDB также завершился таймаутом на 90-й секунде; это не отменяет успешную проверку BB/Vibix. Адаптер запрашивает точно выбранные озвучку и серию и не переиспользует просроченный снимок. Zetflix остаётся недоступен из-за неразрешимого upstream-хоста. Для фильма добавлена узкая защита finite VOD: кандидат отбрасывается, если заявленная длительность меньше половины ожидаемой. Для Fight Club (TMDB fixture id 550, 139 минут; реальный API token не использовался) backend передал `runtimeMinutes=139`; исходный VeoVeo после сбоя ZetflixDB дал полный поток 8349 секунд, 17 декодированных кадров и успешный seek на 60-й секунде с получением новых кадров. Это подтверждает данный фильм и кандидат, но не неизвестные runtime и live/direct потоки; эти случаи остаются ограничением. Повторная проверка S3E1 после последнего развёртывания также прошла: AniMedia, 1470 секунд, декодированные кадры и кнопка пропуска опенинга. Workers Paid не приобретался; relay работает в пределах текущих бесплатных лимитов ([лимиты Cloudflare Workers](https://developers.cloudflare.com/workers/platform/limits/)).

## Проверка и критерии

- Для каждого заявленного работающего источника нужны реальный resolve, доступный плейлист/файл, успешное получение сегмента и декодирование кадра; выдача метаданных сама по себе недостаточна.
- Zetflix и ZetflixDB проверяются отдельно, включая фильм и сериал. Увеличение таймаута не считается исправлением.
- Регрессии: ошибочное совпадение названия/года, неверные сезон или серия, отсутствующая озвучка, HTML вместо видео, 403/404/503, зависание, отмена, небезопасный redirect, истёкший токен, HLS encryption/init и HTTP Range.
- Клиент проверяется браузерными тестами с реальным декодированием. Живые источники проверяются отдельно; новые длительные проверки и полное покрытие аниме остаются открытыми.

Официальный [Lampac NextGen](https://github.com/lampac-nextgen/lampac) содержит адаптеры русских фильмов и аниме. Его [VideoDB](https://github.com/lampac-nextgen/lampac/blob/main/Modules/OnlineRUS/VideoDB/README.md) обслуживает ZetflixDB. Для локальной разработки и параметров облачного контейнера см. [инструкцию инфраструктуры](../infrastructure/lampac/README.md).
