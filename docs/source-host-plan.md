# Новый хост источников

Цель — независимый от vi3000 сервер фильмов, сериалов и аниме с русскими озвучками, несколькими качествами, точным выбором серии и проверенным воспроизведением. Клиент старого сайта не задаёт архитектуру нового сервера.

## Архитектура

- Отдельный Node API и закреплённый Lampac NextGen `1.81.0` с Chromium работают в одном Vercel Container Runtime. Browser запускается скрыто в Xvfb; Lampac и CDP доступны только внутри контейнера. Образ уже собран удалённо, модульный кэш подготовлен заранее и копируется в эфемерный `/tmp` при старте.
- Поиск источников возвращает результаты постепенно. Идентификатор кандидата содержит зашифрованное состояние с ограниченным сроком жизни, поэтому выбранная озвучка переживает смену инстанса без общей памяти. Приватные API требуют серверный ключ; ссылки воспроизведения непрозрачны и подписаны.
- Node API проверяет URL, DNS и каждый redirect. Он обслуживает HTTP Range и HLS, включая относительные сегменты, ключи, init-сегменты и субтитры. Адреса и заголовки поставщика не принимаются от пользователя.
- По умолчанию видео передаётся через Node API контейнера. Необязательный `SOURCE_MEDIA_RELAY_URL` подключает отдельный Cloudflare Worker для потоковой доставки крупных прямых файлов в обход ограничения размера ответа Vercel. Worker получает URL через приватный `GET /v1/media-route` с Bearer-ключом, а ресурсы движка запрашивает у `GET /v1/media` с `x-source-relay-key`. Секреты существуют только на сервере.
- Чтобы холодный запуск не тратил ресурсы без необходимости, Node API стартует первым, а Lampac и браузер поднимаются при первом поиске или разрешении источника. Предварительный модульный кэш сокращает запуск, но не делает его постоянным. Источники и профили Chrome могут потеряться при перезапуске.

## Текущее состояние

Отдельный Vercel source host развёрнут по адресу `https://lampa-source-host.vercel.app` (последний READY deployment `dpl_4sKKyHFvfvFzQEvXr9VpCQx4akC2`); его контейнер размещён во Frankfurt (`fra1`). В настройках **Project Settings → Functions → Default Regions** также нужен Frankfurt: одного `regions` в `vercel.json` недостаточно, чтобы переместить сам контейнер. Фронтенд READY (`dpl_7FUZhCKsUnNGKAvPwj6iMX5E2ybd`) использует собственный source host в разделе «Источники»; встроенный Collaps оставлен как явный резервный источник.

Cloudflare Worker доставки видео развёрнут по адресу `https://lampa-source-media.ocr-gemini-proxy.workers.dev` и подключён к source host через `SOURCE_MEDIA_RELAY_URL`. Ранее для Fight Club/Vibix 1080p и BB/Vibix подтверждены декодирование FFmpeg и seek на 60-й секунде; BB также прошёл браузерные проверки кадра и меню. Haikyuu S1E14 после последнего деплоя прошёл воспроизведение и seek в скрытом браузере; правильный S3E1 остаётся непроверенным. Метаданные TMDB брались из fixtures, без реального API-токена. После последних изменений прошли source-host 22/22 в рабочей и публикационной копиях, client assertions и `git diff --check`. Worker 8/8, Playwright 13/13 и build проходили до этих изменений; клиент и Worker в последнем деплое не менялись.

Свежий ZetflixDB для фильма разрешается и возвращает HLS, но повторные root/segment запросы в облаке завершались `404` или `502`. Кандидат BB/ZetflixDB также завершился таймаутом на 90-й секунде; это не отменяет успешную проверку BB/Vibix. Адаптер запрашивает точно выбранные озвучку и серию и не переиспользует просроченный снимок. Zetflix выдаёт озвучки, но три проверенных варианта Haikyuu S1E14 вернули `MEDIA_UNAVAILABLE`; воспроизведение в облаке не подтверждено. Для фильма добавлена узкая защита finite VOD: кандидат отбрасывается, если заявленная длительность меньше половины ожидаемой. Для Fight Club (TMDB fixture id 550, 139 минут; реальный API token не использовался) backend передал `runtimeMinutes=139`; исходный VeoVeo после сбоя ZetflixDB дал полный поток 8349 секунд, 17 декодированных кадров и успешный seek на 60-й секунде с получением новых кадров. Это подтверждает данный фильм и кандидат, но не неизвестные runtime и live/direct потоки; эти случаи остаются ограничением. Предыдущая проверка S3E1 доказывала декодирование и кнопку пропуска, но не правильность сезона: AniMedia фактически вернул `s=1`. Теперь явный другой сезон отбрасывается; для следующих сезонов без `s` требуется выбранный сезонный endpoint. Workers Paid не приобретался; relay работает в пределах текущих бесплатных лимитов ([лимиты Cloudflare Workers](https://developers.cloudflare.com/workers/platform/limits/)).


Исправлен фильтр аниме: обычные русскоязычные источники теперь участвуют вместе с аниме-провайдерами. Для Haikyuu S1E14 через облачный Vibix/Onibaku подтверждены 720p, декодированный кадр и seek на 60-й секунде. Phantom и Collaps работали в локальной проверке, но облачный decode завершился 5xx; они не считаются подтверждённо работающими. Выбор серии проверяет и `e`, и заявленный `s`, в том числе при обновлении ZetflixDB; старые зашифрованные кандидаты с противоречащим сезоном также отклоняются. Явная заглушка «Заблокировано правообладателем!» исключается из озвучек и resolve. Без маркировки сезона корневой список считается первым сезоном; раздельным сезонным каталогам требуется отдельное сопоставление.

Проверка ZetflixDB на одном локальном процессе дала root/leaf/TS `200` как с полными заголовками, так и с разрешённым набором приложения, без cookie. В облаке свежий resolve может завершиться `200`, но повторный root/segment — `404` или `502` через оба маршрута. Привязка к IP/сессии остаётся гипотезой, а не установленным фактом; расширение набора заголовков и переключение Worker/Node не подтверждены как исправление. Для «Начала» Filmix выдал помеченную заглушку длительностью 3652 секунды вместо ожидаемых 148 минут. Её явная метка теперь отбрасывается, но проверка длительности прямых файлов без такой метки остаётся ограничением: текущая защита длительности относится к конечным HLS VOD.


После исправления сезона браузерный S3E1 дошёл до Filmix/AniLibria (файл 2985 секунд), но seek на 60-ю секунду сбросился к началу; этот выпуск не считается успешно проверенным. Свежий поиск «Начала» после деплоя вернул 42 кандидата без Filmix-заглушки; реальные decode/seek этих 42 кандидатов не подтверждены.


Свежий браузерный S1E14 после этого деплоя прошёл воспроизведение AniMedia (1470 секунд, 16 кадров) и seek на минуту; AniSkip `20583/14` ответил `200`, но в выбранной точке кнопка пропуска не была видна. Метаданные TMDB в этой проверке — fixtures, видео и запросы меток реальные.

## Проверка и критерии

- Для каждого заявленного работающего источника нужны реальный resolve, доступный плейлист/файл, успешное получение сегмента и декодирование кадра; выдача метаданных сама по себе недостаточна.
- Zetflix и ZetflixDB проверяются отдельно, включая фильм и сериал. Увеличение таймаута не считается исправлением.
- Регрессии: ошибочное совпадение названия/года, неверные сезон или серия, отсутствующая озвучка, HTML вместо видео, 403/404/503, зависание, отмена, небезопасный redirect, истёкший токен, HLS encryption/init и HTTP Range.
- Клиент проверяется браузерными тестами с реальным декодированием. Живые источники проверяются отдельно; новые длительные проверки и полное покрытие аниме остаются открытыми.

Его [VideoDB](https://github.com/lampac-nextgen/lampac/blob/main/Modules/OnlineRUS/VideoDB/README.md) обслуживает ZetflixDB. Для локальной разработки и параметров облачного контейнера см. [инструкцию инфраструктуры](../infrastructure/lampac/README.md).
