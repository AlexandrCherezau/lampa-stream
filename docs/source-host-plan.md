# Новый хост источников

Цель — независимый от vi3000 сервер фильмов, сериалов и аниме с русскими озвучками, несколькими качествами, точным выбором серии и проверенным воспроизведением. Клиент старого сайта не задаёт архитектуру нового сервера.

## Архитектура

- Отдельный Node API и закреплённый Lampac NextGen `1.81.0` с Chromium работают в одном Vercel Container Runtime. Browser запускается скрыто в Xvfb; Lampac и CDP доступны только внутри контейнера. Образ уже собран удалённо, модульный кэш подготовлен заранее и копируется в эфемерный `/tmp` при старте.
- Поиск источников возвращает результаты постепенно. Идентификатор кандидата содержит зашифрованное состояние с ограниченным сроком жизни, поэтому выбранная озвучка переживает смену инстанса без общей памяти. Приватные API требуют серверный ключ; ссылки воспроизведения непрозрачны и подписаны.
- Node API проверяет URL, DNS и каждый redirect. Он обслуживает HTTP Range и HLS, включая относительные сегменты, ключи, init-сегменты и субтитры. Адреса и заголовки поставщика не принимаются от пользователя.
- По умолчанию видео передаётся через Node API контейнера. Необязательный `SOURCE_MEDIA_RELAY_URL` подключает отдельный Cloudflare Worker для потоковой доставки крупных прямых файлов в обход ограничения размера ответа Vercel. Worker получает URL через приватный `GET /v1/media-route` с Bearer-ключом, а ресурсы движка запрашивает у `GET /v1/media` с `x-source-relay-key`. Секреты существуют только на сервере.
- Чтобы холодный запуск не тратил ресурсы без необходимости, Node API стартует первым, а Lampac и браузер поднимаются при первом поиске или разрешении источника. Предварительный модульный кэш сокращает запуск, но не делает его постоянным. Источники и профили Chrome могут потеряться при перезапуске.

## Проверка и критерии

Filmix / «Дубляж [Rus, 4K, SDR]» 480p для «Интерстеллара» прошёл проверку в настоящем плеере продакшена: 10144 секунды, 17 кадров при старте и 53 после перемотки на 60,51 секунды. Поиск в этой проверке был ограничен одним ранее выданным настоящим кандидатом; resolve и видео запрашивались реально, TMDB использовал fixtures. Это подтверждает данный фильм и озвучку, но не исправление перемотки Filmix для Haikyuu и не остальные качества.

Клиент теперь принимает `segments.skip` источника и показывает «Пропустить фрагмент». Только конечные числовые интервалы внутри длительности видео допускаются к использованию; реклама из `segments.ad` исключена. Интервалы без типа требуют нажатия даже в режиме «Автоматически», принадлежат текущему потоку и сохраняют сцену после титров. Проверены восстановление предыдущего потока, очистка на новом фильме и браузерный пропуск с реальным тестовым видео в автоматическом режиме при пересечении с post-credits. После обоих READY-деплоев Filmix повторно прошёл запуск и перемотку в настоящем плеере. Source-host прошёл 23/23, браузерный файл плеера — 6/6, client/player assertions и сборка прошли. Метки источника в этих регрессиях — fixtures; наличие таких меток у всех внешних источников не подтверждено.

Alloha проверен только в отдельном локальном движке с модулем OnlinePaid: запрос «Интерстеллара» завершился 503. Он не добавлен в выдачу продакшена и не считается работающим источником.

Cloudflare Worker теперь один раз обращается к приватному Node media-handler, если прямой CDN вернул 403 или 404. В парной проверке одного и того же сегмента ZetflixDB Node вернул 206, а Worker — 404; после обновления свежий сегмент вернул 206 через оба маршрута. Плейлисты также прошли через оба маршрута. Это подтверждает получение сегмента, но не декодирование фильма: FFmpeg завершился 5xx при открытии, а более старый сегмент позже отказал через оба маршрута. Резервный запрос не восстанавливает недоступный на обоих маршрутах ресурс; крупный ответ через Node по-прежнему может упереться в лимит Vercel.

Worker version `1aea1a6f-b76b-4aad-a83b-08517e74c4b4` развёрнута на 100%. Диагностика DNS сообщает имя фактически проверяемого CDN и код ошибки, вместо имени AES-обёртки. Регрессии проверяют отсутствие полных ссылок, параметров, заголовков и приватных сведений в логах, а также сохранение Range/CORS при резервной доставке и отсутствие повторного запроса для 429. Source-host прошёл 25/25, Worker — 11/11. Секретные bindings Worker сохранены; тариф не менялся.

Следующая проверка настоящего плеера ZetflixDB дала 200 для плейлистов, но 502 для сегментов через Worker и ни одного кадра. Тот же проблемный сегмент полностью скачался через Node: 200, 334264 байта, без обрыва; одновременно Worker вернул 502. Поэтому для ZetflixDB добавлена прямая доставка через Node: подписанные quality-ссылки и все дочерние HLS-ресурсы наследуют `nodeOnly`. Другие провайдеры сохраняют прежний маршрут. Поэтому запуск подтверждён, устойчивое воспроизведение и перемотка — нет. Поиск был ограничен одним ранее выданным реальным кандидатом, TMDB использовал fixtures; resolve и видео были реальными.

- Для каждого заявленного работающего источника нужны реальный resolve, доступный плейлист/файл, успешное получение сегмента и декодирование кадра; выдача метаданных сама по себе недостаточна.
- Zetflix и ZetflixDB проверяются отдельно, включая фильм и сериал. Увеличение таймаута не считается исправлением.
- Регрессии: ошибочное совпадение названия/года, неверные сезон или серия, отсутствующая озвучка, HTML вместо видео, 403/404/503, зависание, отмена, небезопасный redirect, истёкший токен, HLS encryption/init и HTTP Range.
- Клиент проверяется браузерными тестами с реальным декодированием. Живые источники проверяются отдельно; новые длительные проверки и полное покрытие аниме остаются открытыми.

Официальный [Lampac NextGen](https://github.com/lampac-nextgen/lampac) содержит адаптеры русских фильмов и аниме. Его [VideoDB](https://github.com/lampac-nextgen/lampac/blob/main/Modules/OnlineRUS/VideoDB/README.md) обслуживает ZetflixDB. Для локальной разработки и параметров облачного контейнера см. [инструкцию инфраструктуры](../infrastructure/lampac/README.md).


Автовыбор больше не исключает весь провайдер после ошибки одной озвучки. Неудачные кандидаты учитываются отдельно; уже найденные провайдеры перебираются по очереди, затем проверяются их другие озвучки. Браузерный тест с реальными кадрами прошёл цепочку 503 → битый HLS → рабочая озвучка того же провайдера и seek на 60-ю секунду. Это проверка механизма на fixtures, а не подтверждение доступности всех внешних источников.

При автоматическом выборе качества слишком короткий HLS VOD теперь исключает только это качество: сервер проверяет остальные варианты той же озвучки. Ручной выбор качества остаётся точным. Регрессия проверяет короткий 720p → полный 1080p, отказ ручного 720p и случай, когда остальные качества недоступны; source-host прошёл 23/23 теста.

Только метаданные TMDB были fixtures; видео и метки запрашивались реально.

Zetflix теперь, как и ZetflixDB, перед resolve обновляет точный same-origin каталог выбранной озвучки и серии. Это восстанавливает нужный нативному движку контекст после смены инстанса; несовпавшие свежие данные отклоняются без обращения к старым call/stream. Регрессия холодного процесса была красной до исправления; полный source-host прошёл 27/27. После READY-деплоя единственный контрольный resolve Haikyuu S1E14 / «MVO | AniLibria.TV» вернул 503 `UPSTREAM_HTTP_ERROR` на обновлении каталога, до media probe. Воспроизведение Zetflix остаётся неподтверждённым.

Плеер теперь использует оставшиеся источники после поздней фатальной сетевой ошибки HLS и сохраняет позицию до отключения HLS. Повторять четыре дополнительных `startLoad` после исчерпания внутренней политики HLS больше не требуется для собственного source host. Регрессия с настоящим FFmpeg-видео проверяет успешный запуск, отказ сегментов после seek на минуту, кадры после переключения и окончательную ошибку при исчерпании пула без третьего resolve. READY-сборка с этим патчем скомпилировала и загрузила модуль в Vercel.
